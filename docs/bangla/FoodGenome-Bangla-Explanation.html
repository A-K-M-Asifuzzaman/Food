১. প্রজেক্টটি আসলে কী

একজন ব্যবহারকারী তার প্লেটের একটি ছবি তোলেন। সিস্টেমটি পাঁচটি জিনিস ফেরত দেয়:

  1. খাবারটি কী — ১০১টি শ্রেণির মধ্যে একটি (যেমন sushi, lasagna)।
  2. কতটা নিশ্চিত — এমন একটি সংখ্যা যার প্রকৃত অর্থ আছে। "৮০% নিশ্চিত" বললে বাস্তবে প্রায় ৮০% ক্ষেত্রেই সঠিক হয়।
  3. যেসব সম্ভাবনা বাতিল করা যাচ্ছে না — একটি প্রার্থী-তালিকা, যার সাথে গাণিতিক নিশ্চয়তা যুক্ত।
  4. মডেল কোথায় তাকিয়েছিল — ছবির উপর একটি তাপচিত্র (heatmap)।
  5. পুষ্টি তথ্য — ৩২টি উপাদান, প্রতিটির উৎস USDA-র নির্দিষ্ট রেকর্ড পর্যন্ত অনুসরণযোগ্য।

এর সাথে একটি প্রশ্নোত্তর ব্যবস্থা আছে যা কেবল তার জানা তথ্যের ভিত্তিতেই উত্তর দেয়, এবং জানা না থাকলে উত্তর দিতে অস্বীকার করে।

কেন এটি সাধারণ প্রজেক্ট থেকে আলাদা বেশিরভাগ ছাত্র-প্রজেক্ট শুধু accuracy দেখায়। কিন্তু accuracy একা যথেষ্ট নয় — একটি মডেল ৯৭% সঠিক হয়েও প্রতিটি উত্তরে "৯৯.৯% নিশ্চিত" বলতে পারে, তখন ব্যবহারকারী ভালো-খারাপ উত্তরের পার্থক্য বুঝতে পারেন না। এই প্রজেক্টে তাই accuracy-র পাশাপাশি calibration (আত্মবিশ্বাস সৎ কি না) এবং conformal prediction (গাণিতিক নিশ্চয়তা) যোগ করা হয়েছে।

২. সমস্যা ও নকশার মূল সিদ্ধান্ত

২.১ হার্ডওয়্যারের সীমাবদ্ধতা

পুরো কাজটি একটি Apple M3 Pro ল্যাপটপ (১৮ GB RAM)-এ করা হয়েছে। কোনো NVIDIA GPU নেই — PyTorch-এর MPS ব্যাকএন্ড ব্যবহার করা হয়েছে, যা Apple-এর নিজস্ব GPU চালায়। এটি একটি A100 GPU-র চেয়ে অনেক ধীর।

এই সীমাবদ্ধতাই সবচেয়ে বড় নকশা-সিদ্ধান্তটি ঠিক করে দিয়েছে: frozen feature bank।

মূল অন্তর্দৃষ্টি একটি ৩০ কোটি প্যারামিটারের মডেল ল্যাপটপে fine-tune করতে ঘণ্টার পর ঘণ্টা লাগে। প্রতিটি পরীক্ষার জন্য এত সময় দিলে হাতে গোনা কয়েকটি পরীক্ষাই করা যাবে। কিন্তু যদি বড় মডেলটি একবারই সব ছবির উপর চালিয়ে ফলাফল (embedding) ডিস্কে জমা রাখি, তাহলে পরবর্তী প্রতিটি পরীক্ষা — head-এর গঠন, calibration, conformal, ensemble — সেকেন্ডে শেষ হয়। এই একটি সিদ্ধান্তের কারণেই প্রজেক্টটি বৈজ্ঞানিকভাবে কঠোর হতে পেরেছে।

৫. ডেটা বিভাজন — সবচেয়ে গুরুত্বপূর্ণ ধাপ

এই প্রজেক্টের সবচেয়ে সাধারণ ভুল যেটি এড়ানো হয়েছে Food-101-এ কেবল train আর test আছে — কোনো validation নেই। অনেকে তাই টেস্ট সেট দেখে সিদ্ধান্ত নেন ("কোন epoch ভালো?", "কোন মডেল রাখব?")। এতে টেস্টের সংখ্যা অতিরঞ্জিত হয়ে যায়, কারণ টেস্ট সেট আর নিরপেক্ষ থাকে না। এটিকে বলে data leakage।

সমাধান: train থেকেই ৪% কেটে নিয়ে val বানানো হয়েছে। সব সিদ্ধান্ত val-এ, আর test কেবল একদম শেষে একবার।

src/nutrivision/data/dataset.py 
def holdout_mask(targets, num_classes, val_fraction, seed=SEED):
    """শ্রেণি-ভিত্তিক (stratified) নির্দিষ্ট validation মাস্ক।

    ছবি-পাইপলাইন আর cached-feature পাইপলাইন — দুটোই একই ফাংশন ব্যবহার
    করে, যাতে দুই জায়গায় একই ছবি val-এ পড়ে। এখানে সামান্য অমিল হলেই
    validation নমুনা প্রশিক্ষণে ঢুকে যাবে এবং পরের সব সংখ্যা ফুলে যাবে।
    """
    rng = np.random.default_rng(seed)      # নির্দিষ্ট seed = পুনরাবৃত্তিযোগ্য
    is_val = np.zeros(len(targets), dtype=bool)
    for label in range(num_classes):
        idx = np.flatnonzero(targets == label)   # এই শ্রেণির সব সূচক
        rng.shuffle(idx)
        n_val = max(1, int(round(len(idx) * val_fraction)))
        is_val[idx[:n_val]] = True               # প্রথম n_val টি val-এ
    return is_val

যদি পুরো ডেটা থেকে এলোমেলোভাবে ৪% নিতাম, তাহলে কোনো শ্রেণির হয়তো ৫০টি নমুনা আসত, আবার কোনোটির ২০টি। শ্রেণি-ভিত্তিক ভাগ করলে প্রতিটি শ্রেণি থেকেই সমান অনুপাতে নমুনা আসে, ফলে val সেটটি পুরো সমস্যার প্রতিনিধিত্ব করে।

৬. ধাপ ১: Feature Bank

৬.১ ধারণাটি কী

একটি বড় pretrained মডেল (backbone) একটি ছবিকে একটি সংখ্যার ভেক্টরে রূপান্তর করে — একে বলে embedding বা feature। এই ভেক্টরে ছবির "অর্থ" ধরা থাকে: দুটি সুশির ছবির ভেক্টর কাছাকাছি হবে, সুশি আর পিৎজার ভেক্টর দূরে থাকবে।

মূল কৌশল: backbone-টিকে একবারই সব ছবির উপর চালিয়ে সেই ভেক্টরগুলো ডিস্কে জমিয়ে রাখা। এরপর আর কখনো বড় মডেল চালাতে হয় না।

def extract(spec, split, batch_size, workers, image_size, flip, limit=None):
    model, transform, cfg = build_backbone(spec, image_size)
    ds = Food101Folder(split=split, transform=transform, val_fraction=0.0)
    loader = DataLoader(ds, batch_size=batch_size, shuffle=False,
                        num_workers=workers)

    # float16 — অর্ধেক জায়গা, নির্ভুলতায় কার্যত কোনো ক্ষতি নেই
    feats  = np.zeros((len(ds), spec.dim), dtype=np.float16)
    labels = np.zeros(len(ds), dtype=np.int64)
    cursor = 0

    autocast = torch.autocast(device_type=DEVICE.type, dtype=torch.float16,
                              enabled=DEVICE.type != "cpu")
    for images, target in tqdm(loader):
        images = images.to(DEVICE, non_blocking=True)
        with autocast:
            out = model(images)         # (B, dim) — pooled embedding
            if flip:                    # বিকল্প: আয়না-ছবির সাথে গড়
                out = (out + model(torch.flip(images, dims=[3]))) / 2
        n = out.shape[0]
        feats[cursor:cursor + n] = out.float().cpu().numpy().astype(np.float16)
        labels[cursor:cursor + n] = target.numpy()
        cursor += n

    np.save(out_dir / f"{split}_x.npy", feats)   # ভেক্টর
    np.save(out_dir / f"{split}_y.npy", labels)  # লেবেল

৭.২ Gated Fusion — দুটি backbone একসাথে

দুটি backbone-এর ভেক্টর কেবল জোড়া দিলে (concatenate) একটিই ওজন-ম্যাট্রিক্সকে দুটি ভিন্ন স্কেলের স্থান সামলাতে হয়। বদলে, প্রতিটিকে একই আকারে প্রক্ষেপণ করে একটি gate শেখানো হয়, যা প্রতিটি ছবির জন্য আলাদাভাবে ঠিক করে কোন backbone-কে কতটা বিশ্বাস করা হবে।

src/nutrivision/models/heads.py 
class GatedFusionProbe(nn.Module):
    def __init__(self, dims, num_classes, proj=1024, hidden=1536, dropout=0.3):
        super().__init__()
        # প্রতিটি backbone-কে একই প্রস্থে আনা
        self.projections = nn.ModuleList(
            nn.Sequential(nn.LayerNorm(d), nn.Linear(d, proj), nn.GELU())
            for d in dims
        )
        # gate: কোনটিকে কত ওজন — যোগফল ১
        self.gate = nn.Sequential(
            nn.Linear(proj * len(dims), len(dims)),
            nn.Softmax(dim=-1),
        )
        self.head = nn.Sequential(
            nn.LayerNorm(proj), nn.Linear(proj, hidden), nn.GELU(),
            nn.Dropout(dropout), nn.LayerNorm(hidden),
            nn.Linear(hidden, num_classes),
        )

    def forward(self, xs, return_gate=False):
        projected = [p(x) for p, x in zip(self.projections, xs)]
        stacked   = torch.stack(projected, dim=1)          # (B, M, proj)
        weights   = self.gate(torch.cat(projected, -1)).unsqueeze(-1)
        fused     = (stacked * weights).sum(dim=1)         # ওজনসহ যোগ
        logits    = self.head(fused)
        return (logits, weights.squeeze(-1)) if return_gate else logits

৭.৩ Embedding-স্থানে Mixup

Mixup একটি নিয়মিতকরণ (regularization) কৌশল: দুটি নমুনা ও তাদের লেবেল মিশিয়ে নতুন প্রশিক্ষণ-উদাহরণ বানানো হয়। ছবি জমে যাওয়ার পর পিক্সেলে mixup করা যায় না, কিন্তু ভেক্টরে করা যায় এবং তাতে খরচও নেই।

def mixup_features(x, y, num_classes, alpha, smoothing):
    off = smoothing / num_classes
    on  = 1.0 - smoothing + off
    targets = torch.full((y.size(0), num_classes), off, device=y.device)
    targets.scatter_(1, y.unsqueeze(1), on)     # label smoothing

    if alpha <= 0:
        return x, targets

    lam  = float(torch.distributions.Beta(alpha, alpha).sample())
    perm = torch.randperm(x.size(0), device=x.device)
    # ভেক্টর ও লেবেল — দুটোই একই অনুপাতে মেশানো
    return lam * x + (1 - lam) * x[perm], lam * targets + (1 - lam) * targets[perm]

১০.২ সমাধান: Temperature Scaling

একটি মাত্র সংখ্যা T শেখা হয়। softmax-এর আগে logits-কে T দিয়ে ভাগ করা হয়:

p = softmax(logits / T)
  • T > 1 → বিতরণ নরম হয় → আত্মবিশ্বাস কমে
  • T < 1 → বিতরণ ধারালো হয় → আত্মবিশ্বাস বাড়ে
গুরুত্বপূর্ণ ধর্ম ভাগ করা সব শ্রেণিতে সমানভাবে হয়, তাই সবচেয়ে বড় মান কোনটি তা বদলায় না। অর্থাৎ accuracy গাণিতিকভাবে অপরিবর্তিত থাকে — শুধু আত্মবিশ্বাসের সংখ্যাটি ঠিক হয়। ফলাফলে দেখা যায় দুটোই ৯৭.১৫৬%।

def fit_temperature(logits, y, max_iter=200):
    """validation-এ NLL সর্বনিম্ন করে এমন একটি scalar T খোঁজা।"""
    log_t = torch.zeros(1, requires_grad=True)   # log-স্থানে, যাতে T > 0
    opt = torch.optim.LBFGS([log_t], lr=0.1, max_iter=max_iter)

    def closure():
        opt.zero_grad()
        loss = F.cross_entropy(logits / log_t.exp(), y)
        loss.backward()
        return loss
    opt.step(closure)
    return float(log_t.exp())

def conformal_quantile(scores, alpha):
    n = len(scores)
    # সসীম নমুনার সংশোধন: ceil((n+1)(1-alpha)) / n
    level = math.ceil((n + 1) * (1 - alpha)) / n
    return float(np.quantile(scores, min(level, 1.0), method="higher"))

২০. সীমাবদ্ধতা

একটি সৎ প্রজেক্টে সীমাবদ্ধতা বলা আবশ্যক:

  1. মাত্র ১০১টি শ্রেণি। এর বাইরের খাবার দেখালে সিস্টেম ভুল উত্তর দেবে বা প্রত্যাখ্যান করবে।
  2. পরিমাণ অনুমান করা হয় না। ছবি থেকে খাবারের ওজন মাপা হয় না; একটি আদর্শ পরিবেশন ধরে নেওয়া হয়। প্লেটে দ্বিগুণ খাবার থাকলে সংখ্যা দ্বিগুণ হওয়া উচিত ছিল।
  3. একটি প্লেটে একটি খাবার। একাধিক পদ থাকলে শুধু প্রধানটিই শনাক্ত হয়।
  4. Composite রেসিপি আনুমানিক। ৬০টি খাবারের পুষ্টি সাধারণ রেসিপি থেকে গণনা করা — নির্দিষ্ট রেস্তোরাঁর রান্নার সাথে ভিন্ন হতে পারে।
  5. Conformal গ্যারান্টি শর্তসাপেক্ষ। calibration ও test ডেটা exchangeable হলেই কেবল প্রযোজ্য। খুব ভিন্ন ধরনের ছবিতে গ্যারান্টি ভেঙে যেতে পারে।
  6. চিকিৎসা পরামর্শ নয়। এটি শিক্ষামূলক প্রকল্প।
